    27→## What is Atropos?
    28→Atropos is an environment microservice framework for async RL with LLMs.
    29→
    30→Atropos encompasses both environments, which are set up as services, and a trajectory API for the environments to send data to and for the trainer to pull batches from.
    31→
    32→![image](https://github.com/user-attachments/assets/8ce52994-b219-49d6-970c-58a477f36151)
    33→<div align="center">
    34→
    35→  *Here is a diagram of how Atropos' components can interact with a trainer & inference server to complete the RL loop (trainer & inference engine not included with the atropos package)*
    36→
    37→</div>
    38→
    39→Atropos is a robust, scalable framework for **Reinforcement Learning Environments with LLMs**.
    40→
    41→The goal: provide a flexible, scalable, and standardized platform to accelerate LLM-based RL research across diverse, interactive settings.
    42→
    43→The framework supports collecting, distributing and evaluating LLM trajectories through diverse environments including:
    44→
    45→<div align="center">
    46→
    47→| Environment Type          | Examples                                   | Purpose                                            |
    48→|---------------------------|--------------------------------------------|----------------------------------------------------|
    49→| 📚 Dataset environments   | GSM8K, MMLU, Custom HF Datasets            | Evaluate and improve LLM performance on static data|
    50→| 🎮 Online environments    | Blackjack, Taxi, Text-based games          | Train LLMs through interactive game-based learning |
    51→| 🤖 RLAIF and RLHF         | LLM Judge/Reward Models                    | Fine-tune LLMs using human feedback and alignment  |
    52→| 🔄 Multi-Turn RL          | deepresearch, internal tool calling        | Train LLMs on complex multi-step interactions      |
    53→| 💻 Code Execution         | MBPP, HumanEval (via `coding_server.py`)   | Train LLMs to generate and execute code            |
    54→| 🖼️ Multimodal             | OCR VQA, Clevr (via `multimodal_dpo/`)     | Train LLMs on tasks involving vision and language  |
    55→
    56→</div>

   139→## Installation
   140→
   141→Get your Python 3.10 (or later) environment ready, then simply pip install:
   142→
   143→```bash
   144→pip install atroposlib
   145→```
   146→
   147→If you're looking to get into developing the repo or using the environments:
   148→
   149→
   150→```bash
   151→pip install -e .                # for using
   152→pip install -e .[dev]           # for development
   153→pip install -e .[examples]      # for running examples
   154→pip install -e .[all]           # for everything
   155→```
   156→
   157→**Important:** If you're committing to the repository, please install the pre-commit hooks:
   158→```bash
   159→pre-commit install
   160→```

   164→### Quick Start Guide
   165→
   166→1. **Create Your First Environment**
   167→   - Review our [Base Class Documentation](atroposlib/envs/README.md) to understand the core concepts
   168→   - Check out existing environments in the [`environments/`](environments) directory for examples
   169→
   170→2. **Run an Example Environment**
   171→
   172→  You should edit the config_init section of the environment file you want ([For example, in GSM8K Environment](https://github.com/NousResearch/atropos/blob/main/environments/gsm8k_server.py#L53)) to point to a running VLLM or SGLang inference server as well as any other [configuration changes](CONFIG.md) you'd like to make, such as the group size, then:
   173→
   174→  > **Note:** By default, Atropos uses the OpenAI-compatible API endpoint which works with any provider. For enhanced features, use `VLLMServer` (atroposlib/envs/server_handling/vllm_server.py) or `SGLangServer` (atroposlib/envs/server_handling/sglang_server.py) for direct access to native APIs with full token and logprob tracking.
   175→
   176→   ```bash
   177→   # Start the API server
   178→   run-api
   179→   ```
   180→   In a separate terminal, start the GSM8K environment microservice
   181→   ```bash
   182→   python environments/gsm8k_server.py serve --openai.model_name Qwen/Qwen2.5-1.5B-Instruct --slurm false
   183→   # alternatively
   184→   # python environments/gsm8k_server.py serve --config environments/configs/example.yaml
   185→   # python environments/gsm8k_server.py serve --config environments/configs/example.yaml --env.group_size 8 # cli args override corresponding config settings
   186→   ```
   187→3. **Grabbing Rollouts**
   188→
   189→  If you want to just start getting rollouts, and not use a trainer, see the [debug section](#testing-and-debugging-tools)
   190→  for help getting started with the available tools, we recommend starting with process or view-run
   191→
   192→4. **Training Your Model**
   193→   - Follow our [training example guide](example_trainer/README.md) for detailed instructions
   194→   - Monitor progress through our built-in logging and reporting system:
   195→     - Completion lengths
   196→     - Evaluation accuracies
   197→     - Full rollouts and scores
   198→
   199→You can use multiple environments at once, just point them all to the same server.
   200→
   201→Environments come with detailed logging and reporting support, runs track completion lengths, eval accuracies, full rollouts and scores, and more:
   202→
   203→![image](https://github.com/user-attachments/assets/153a2932-191a-42e3-8da9-25a1b05abb8e)

   223→## Tinker
   224→<a href="https://github.com/NousResearch/tinker-atropos">
   225→  <img
   226→    src="https://github.com/user-attachments/assets/6c226187-4df8-4094-be5d-72f3f58de423"
   227→    alt="Atropos Tinker logo"
   228→    width="50%">
   229→</a>
   230→
   231→The Tinker API is a simple and flexible LoRA trainer framework for researchers and developers to quickly build out their ideas without worrying about the complexities of distributed training. Users write a simple loop that runs on their CPU, and Tinker manages the backend computation on their GPUs, while still providing full control over the training and algorithmic details.
   232→
   233→The [Tinker-Atropos](https://github.com/NousResearch/tinker-atropos) integration layer enables all Atropos environments to leverage the power of Tinker for their RL experiments. This allows users with little or no compute to develop and build Atropos environments with minimal worry about the underlying compute behavior, as well as providing an easy environment integration point for Tinker users.
   234→
   235→To get started, check out the README at the [project repository](https://github.com/NousResearch/tinker-atropos).

   244→## Testing and Debugging Tools
   245→
   246→The trajectory-handler provides several debugging tools to help environment developers test and understand their environments locally without requiring the full distributed infrastructure.
   247→
   248→*   **Flexible Model Provider Support:** Atropos natively supports any model provider that adheres to the OpenAI API standard. Simply provide the provider's base URL and your API key, and Atropos can integrate with their models seamlessly for testing or running environments locally.
   249→
   250→After launching the API and your selected environments (e.g. `run-api & python environments/gsm8k_server.py serve`), you are then able to view them to get a quick look, or try to prepare some datasets for some offline training:
   251→
   252→*   **View Run (`view-run`):** Launch a Gradio UI to inspect batches of rollouts generated by your environment runs. This is useful for visually debugging the interactions and data flow.
   253→*   **Offline Data Generation:** Use `atropos-sft-gen` and `atropos-dpo-gen` to collect rollouts from environments and convert them into formats suitable for Supervised Fine-Tuning (SFT) or Direct Preference Optimization (DPO).
   254→
   255→### In-depth Local Environment Analysis with `process`
   256→
   257→For developers looking to inspect and debug a single environment without the overhead of the `run-api` server or a full training loop, Atropos environments offer a `process` subcommand. This mode performs inference-only rollouts, meaning it runs your model within the environment to generate interactions, but does not perform any model training or updates.
   258→
   259→The `process` subcommand executes the environment's full data pipeline:
   260→
   261→1.  **Generation:** Produces model responses based on inputs from the environment.
   262→2.  **Parsing:** Processes these raw model outputs into a structured format.
   263→3.  **Scoring:** Applies the environment's reward logic to evaluate the quality of the generated responses.
   264→
   265→**Outputs and Visualization:**
   266→
   267→When you specify a path to save the generated data using the `--env.data_path_to_save_groups your_output_file.jsonl` argument (or a similar argument defined by the specific environment, check with `--help`), the `process` command provides several benefits:
   268→
   269→*   **JSONL Output:** Saves all generated rollout groups, including prompts, responses, and scores, to the specified `.jsonl` file. This data can be useful for detailed offline analysis and debugging.
   270→*   **Static HTML Visualization:** Automatically generates a corresponding `.html` file (e.g., `your_output_file.html`) that provides a user-friendly, browser-based view of the rollouts contained in the JSONL file. This is excellent for quickly understanding model behavior and identifying issues.
   271→*   **WandB Logging:** If Weights & Biases (`use_wandb=True`) is enabled in your environment's configuration, the `process` subcommand will also log the run data, metrics, and generated rollouts to your WandB dashboard, allowing for persistent tracking and comparison even for these inference-only runs.
   272→
   273→**Example Usage:**
   274→
   275→To run the `process` subcommand for an environment like `gsm8k_server.py` and save the outputs:
   276→
   277→```sh
   278→python environments/gsm8k_server.py process --env.data_path_to_save_groups gsm8k_rollouts.jsonl
   279→```
   280→
   281→This will create `gsm8k_rollouts.jsonl` and `gsm8k_rollouts.html`.
   282→
   283→**Customization:**
   284→
   285→You can customize the inference endpoint and other parameters for the `process` subcommand. For example, to use a different model or API endpoint:
   286→
   287→```sh
   288→python environments/gsm8k_server.py process \
   289→  --env.data_path_to_save_groups gsm8k_rollouts.jsonl \
   290→  --env.my_custom_field "value" \
   291→  --openai.base_url https://your-custom-api-url/v1 \
   292→  --openai.api_key YOUR_API_KEY \
   293→  --openai.model_name your_model_identifier
   294→```
   295→
   296→You can add custom fields to the `env` namespace by returning a custom subclass of BaseEnvConfig in `config_init` [[example](https://github.com/NousResearch/atropos/blob/bdb15e5d85ddcf8a6ede352977719df442e60a22/environments/math_server.py#L181)].
   297→
   298→Always refer to the specific environment script's help for all available options:
   299→
   300→```sh
   301→python environments/your_environment_script.py process --help
   302→```

   305→
   306→For running evaluation on environments, Atropos provides an `evaluate` subcommand that calls the environment's `evaluate` method:
   307→
   308→```sh

   312→  --openai.model_name qwen/qwen3-14b
   313→```

   325→atropos-sft-gen path/to/output.jsonl --tokenizer Qwen/Qwen2.5-1.5B-Instruct # or whichever tokenizer you have in your env config
   326→```
   327→Rejection sampling can be controlled via `--save-top-n-per-group`, `--allow-negative-scores`, and `--minimum-score-diff-max-min`. See `atropos-sft-gen -h` for more detailed usage info.
   328→
   329→If you would like to use OpenAI models, please edit your `config_init` to something like the following:
   330→```python
   331→    @classmethod
   332→    def config_init(cls) -> Tuple[BaseEnvConfig, List[APIServerConfig]]:
   333→        env_config = BaseEnvConfig(
   334→            tokenizer_name="Qwen/Qwen2.5-1.5B-Instruct",
   335→            group_size=8,
   336→            use_wandb=True,
   337→            rollout_server_url="http://localhost:8000",
   338→            total_steps=1000,
   339→            batch_size=12,
   340→            steps_per_eval=100,
   341→            max_token_length=2048,
   342→            wandb_name="gsm8k",
   343→        )
   344→        server_configs = [
   345→            APIServerConfig(
   346→                model_name="gpt-4.1-nano",
   347→                base_url=None,
   348→                api_key=os.environ.get("OPENAI_API_KEY"),
   349→                num_requests_for_eval=256,
   350→            ),
   351→        ]
   352→
   353→        return env_config, server_configs
   354→```
   355→
   356→For DPO, replace `atropos-sft-gen` with `atropos-dpo-gen` and check `atropos-dpo-gen -h` for data filtering and saving options.
